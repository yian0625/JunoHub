# SMTP 邮箱验证码

后端支持 SMTP 和 Resend。注册表单、验证码校验和发送限制使用同一流程。SMTP 发件地址可以是你自己的 QQ、Gmail 等邮箱，不需要另购域名。

## 配置

在项目根目录 `.env` 填写以下变量，使用邮箱提供的授权码或应用专用密码，不使用网页登录密码：

```dotenv
JUNOHUB_EMAIL_PROVIDER=smtp
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_SECURITY=tls
SMTP_USERNAME=你的邮箱@qq.com
SMTP_PASSWORD=你的邮箱授权码
SMTP_FROM="JunoHub <你的邮箱@qq.com>"
JUNOHUB_EMAIL_DAILY_LIMIT=100
```

| 邮箱 | 服务器 | TLS 端口 | STARTTLS 端口 |
| --- | --- | --- | --- |
| QQ 邮箱 | `smtp.qq.com` | 465 | 以邮箱官方设置为准 |
| Gmail | `smtp.gmail.com` | 465 | 587 |
| 其他邮箱 | 提供商文档中的 SMTP 主机名 | 提供商指定端口 | 提供商指定端口 |

`SMTP_SECURITY=tls` 表示连接建立时使用 TLS，未填写端口时默认 465。`starttls` 表示强制升级到 TLS，未填写端口时默认 587。不支持明文、可选加密或忽略证书校验。

`SMTP_FROM` 应使用该账号获准发送的邮箱地址；QQ、Gmail 通常直接填与 `SMTP_USERNAME` 相同的邮箱。SMTP 不使用 `RESEND_FROM`，也不会发送失败后自动转用 Resend。未设置 `JUNOHUB_EMAIL_PROVIDER` 时仍默认使用 Resend，兼容原有部署。

授权码只保存在后端 `.env`，不要发到聊天或提交 Git，也不能使用 `NEXT_PUBLIC_` 前缀。建议用专门的邮箱发验证码。邮箱自身的额度和风控独立生效；项目默认每 24 小时最多尝试发送 100 次。

### 获取凭证

- QQ 邮箱：设置 → 账号与安全 → 安全设置 → 开启 SMTP 服务 → 生成授权码。按邮箱界面完成身份验证。[官方说明](https://help.mail.qq.com/detail/106/985)
- Gmail：开启两步验证后，在 Google 账号中生成应用专用密码。某些账号可能不提供此选项。[官方说明](https://support.google.com/mail/answer/185833)

### 应用配置

首次接入需要构建后端：

```sh
docker compose up -d --build --no-deps junohub-server
```

以后只修改邮箱配置时，无需重新构建，重建后端容器即可：

```sh
docker compose up -d --no-deps --force-recreate junohub-server
```

## 验证与错误

打开 `/register`（登录页提供“创建账户”链接），输入尚未注册、可以收信的邮箱，点击“获取验证码”。收到验证码后填写验证码、至少 8 个字符的密码，以及可选显示名称，再点击“创建账户”。成功后自动进入个人总览。发送成功只代表 SMTP 服务器接受了邮件；仍需查看收件箱和垃圾邮件箱确认实际送达。

- 缺少配置时，会具体指出 `SMTP_HOST`、`SMTP_USERNAME`、`SMTP_PASSWORD` 或 `SMTP_FROM`，不占用发送次数。
- 认证失败时提示检查账号、授权码与 SMTP 服务；TLS 失败提示检查端口、模式和证书；连接失败提示检查主机名和网络。
- SMTP 拒绝邮件或连接超时时，验证码不可用于注册。失败尝试仍计入频率限制；不会自动重试可能已经送达的邮件。
- 验证码为 6 位数字，5 分钟内有效，最多输错 5 次，60 秒可重新获取，同一邮箱每天最多 10 次。
- 本机模拟 SMTP 测试覆盖 TLS、STARTTLS、身份认证、纯文本/HTML 邮件、认证失败、邮件拒收、无效证书和拒绝加密降级。测试不向真实邮箱发信。

其他部署环境仍需单独配置真实邮箱与授权码；本地 `.env` 不随代码分发。
