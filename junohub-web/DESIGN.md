# JunoHub UI 设计规范

适用于 `app/` 和 `components/` 下的登录、网关控制台和用户管理界面。修改 UI 前阅读本文件；新增规则须对应实际发现的问题。方法参考：[Vercel design.md 文章](https://vercel.com/blog/how-our-agents-build-on-brand-pages-with-design-md)。这里使用 JunoHub 自己的品牌和组件。

## 用户与任务

JunoHub 是私有部署的模型网关。用户需要查看调用用量、连接供应商、配置模型路由、分配访问密钥、排查请求；管理员还需要管理用户。

- 总览沿用原有的四张指标卡与下方双栏快速开始；Token 用量在其后单独展示，保持已有信息完整。
- 客户端接入位于独立的“集成”导航分组。统一供应商是长期保存的管理实体，支持 JunoHub、NewAPI 和自定义网关，可新增、编辑、复制、删除，并为 Claude、Codex、Gemini 分别设置启用状态和模型。外部 API Key 加密保存且不在列表或编辑接口返回；同步时才通过十分钟有效、只能兑换一次的凭证交给 Rust 本地组件。
- 客户端生命周期与供应商管理使用两个独立页面。供应商页面沿用 CC Switch 的客户端切换视角：先选择 Claude、Codex 或 Gemini，再查看该客户端可用的供应商、当前使用状态并切换；卡片提供启用、复制、编辑和删除。复制和新建只保存配置，由用户明确启用；当前正在使用的供应商不能删除；添加和编辑使用居中弹窗，当前使用的配置保存后同步，未使用的配置只保存。客户端页面显示当前版本、最新版本、未安装或不可运行状态，并提供检测、安装和更新。Claude Code、Codex、Gemini CLI 的配置写入前备份，Codex 保留官方登录；页面通过 Rust 本机回环接口执行操作并等待真实结果，不能跳转自定义协议、打开外部应用或用前端计时推断成功。
- 总览页标题旁不放操作按钮；配置入口保留在资源区和接入步骤中。
- 供应商、模型、密钥页：名称、标识、真实状态和管理操作优先。
- 日志和用户管理：表格占满内容宽度，操作与分页保持可见。
- 登录页优先保证表单易读、错误可恢复。登录与注册请求失败时不跳转或刷新页面，错误以表单内 `role="alert"` 持续显示，保留已填内容并允许重试；仅已认证接口的 401 执行登录状态过期跳转。网络错误使用明确中文提示。登录后端返回明确原因和字段：邮箱未注册、密码不正确、账户停用；邮箱／密码错误显示在对应输入框下并聚焦该字段，账户或服务错误显示在表单内。不展示深浅主题切换按钮，沿用应用全局主题；未设置偏好时默认跟随系统主题。
- 普通用户使用“个人总览、可用模型、我的密钥、请求日志、接入指引”，保留个人客户端集成。供应商和模型路由管理仅限管理员，直接访问旧地址跳转到对应个人页面，服务端接口也拒绝越权。总览只汇总本人请求、Token、密钥及估算消耗；可用模型只返回公开别名、客户端接口、能力、价格与供应商头像展示信息，不返回供应商管理实体、上游模型、鉴权或上游路径。接入指引可阅读和下载，只有管理员可编辑。
- 模型目录、网关模型列表与实际调用使用相同授权规则：管理员管理和调用自己的路由，普通用户可调用已启用管理员的开放路由，并保留原有本人路由的调用兼容性。路由和供应商必须启用；同名时本人路由优先，其余按最早有效路由稳定选择。请求和异步任务始终归调用者，费用读取实际路由价格。日志在服务端限制本人范围，普通用户复用管理员相同的搜索、状态、日期、表格列和详情组件，用户及供应商信息仅来自本人的请求记录；伪造用户筛选不能读取其他账户日志。

模型路由与可用模型共用 ModelCatalogCard、ModelCatalogSearch、ModelCatalogGrid 和 ModelCatalogDetails，底层复用 ResourceCard compact、ResourceGrid、ProviderAvatar 与 coss ui 搜索、Button、Badge；保持原有字体与语义色。搜索配模型类型 SelectField 下拉，不展示类型 Tab；结果按模型类型分区。卡片展示真实类型/能力、接口、返回方式、价格和可复制调用名；价格与接入详情展示完整客户端地址与 curl/Python/JavaScript 示例。管理员保留编辑与删除，请求限制合并到编辑表单，上游模型与地址仅在管理员详情出现。普通用户没有上游配置。缺少规格不猜填，配置启用不声称供应商健康。

接入指引采用文档目录与正文两栏，窄屏目录进入正常流。目录由 Markdown AST 的实际二级标题生成，代码块内标题不纳入；重复标题有独立锚点。代码只在局部横向滚动并可键盘聚焦。页面可选择真实可用模型生成接入示例，示例语言 Tab 仅用于切换代码，不用于模型类型筛选。成熟对话协议与兼容向量格式生成最小请求，扩展接口读取管理员按供应商要求准备的 request.json，不编造统一媒体字段。示例仅含环境变量占位密钥；复制动态地址只在浏览器 origin 就绪后启用。Markdown 保留保存/撤销/草稿恢复与版本校验；新版模板自动用于未编辑的默认文档，已保存自定义文档不覆盖，管理员可显式载入模板为草稿。

向量化（Embeddings）接口的模型价格只配置输入单价，单位为美元／百万 Token；路由卡片和可用模型不展示输出价格。用量以供应商返回的输入 Token 为准，兼容接口仅返回 total_tokens 时作为输入 Token 读取；不按向量维度、返回数组长度或响应字节数收费。未返回用量时标记未计价。

模型价格提供 Token、张、秒、字符和次五种明确计费单位；向量化固定输入 Token。字段按所选单位展示，秒和字符必须指定供应商响应中的实际用量 JSON Pointer；图片默认统计有效返回图片，也可配置实际张数字段。留空为未配置，0 为免费，不从请求 n、文本长度或估算时长生成账单。模型路由与可用模型共用 ModelBillingSummary；日志详情显示实际计费用量、单价、金额或未计价原因，普通用户与管理员共用详情组件。字体、卡片、Input、SelectField 与折叠区维持原有样式。

已接受的异步任务由后端持续查询和幂等结算，使用提交时的凭证和价格快照；用户关闭页面不影响处理。停用/删除路由只阻止新调用，已接受任务凭原访问密钥与当前模型范围查询；撤销密钥或停用用户仍阻止客户端读取，后台账务继续记录。任务超时标记未知用量与未计价，不重发生成请求。

邮箱注册使用后端配置的 SMTP 或 Resend 发送 6 位验证码，本地配置为 Gmail SMTP。注册拥有独立 `/register` 地址，登录与注册用真实链接切换，共用 `AuthPage` 的 1024px 双栏布局、原有字体和全局主题。1024px 以上使用品牌区与表单区 0.9:1.1 的两栏；表单居中，最大宽度 384px。较窄屏幕收起品牌介绍，保留 Logo 与字标，单栏卡片最大宽度 480px，避免平板上输入框过长。登录页保留原有品牌标题、说明与三项带描述的功能简介，表单垂直居中；美化组件不删减或改写内容。错误与长文字出现时卡片可自然增高。注册按邮箱、验证码、密码、可选显示名称排列；输入直接使用 coss ui `Input` 与 `InputGroup`；认证按钮直接使用项目已有的 shadcn/ui `Button`（`components/ui/button.tsx`），标签和错误复用 `Field`。普通输入和提交按钮为 44px；认证区域卡片使用 20px 圆角，输入框、验证码与图标框采用 coss ui 官方 Toggle 示例的 10px 圆角（局部 --radius: .625rem）；主按钮使用胶囊圆角与实色蓝色，验证码按钮使用胶囊轻描边，密码显隐按钮使用圆形 ghost 样式；表单使用 raised 表面。认证区域同时局部设置 radius 及其 sm/md/lg/xl 派生 token，保证 coss ui 内部高光层圆角与控件外层一致，Logo 不使用百分比圆角。

邮箱验证码直接使用官方 coss ui `OTPField`、`OTPFieldInput` 源码及 Base UI OTP Field 原语，接口位于 `components/ui/otp-field.tsx`。六格独立成行，使用组件默认尺寸；发送按钮放在标签右侧。保留组件原生的数字过滤、粘贴、自动移位、退格与自动填充，不自行重写键盘行为，不自动提交账户创建。根节点受控绑定完整验证码，第一格继承字段名称，其余格提供中文位置名称。验证码错误标记全部六格并聚焦第一格。手机仅缩小格间距，不能挤压或裁切输入。

密码组合提供可键盘操作的显示／隐藏按钮。发送成功后显示收件邮箱和 60 秒重发倒计时；邮箱改变时清除旧验证码与查收提示。验证码 5 分钟有效，服务端强制校验并限制错误次数；发信服务故障显示在表单内。发送或提交期间禁止重复操作，失败保留其他已填内容；现有账户登录不要求验证码。

认证表单的按钮和独立输入框使用 2px 实线键盘焦点；密码组合在外层显示焦点，不依赖浅色阴影单独表达选中位置。

## 可观察的设计规则

1. 保留 JunoHub 标志与字标。蓝色只用于主操作、选中导航和功能链接；状态色必须配文字或图标。
2. 浅色主题采用低饱和灰蓝画布、略亮的卡片与侧栏，顶栏与侧栏同为明亮实色表面，避免大面积纯白。使用实色表面与细边框，不使用玻璃模糊、装饰性渐变和大面积阴影。深色主题使用炭灰蓝而非近纯黑：侧栏最深、画布次之、卡片与弹出层逐级提亮；主文字为柔白，辅助文字保持足够对比。Logo、输入框、描边按钮都随主题变化。
3. 桌面使用贴边侧栏与贴顶栏。侧栏展开宽 240px、折叠宽 80px；导航行高 40px、图标 18px，分组用留白区分，选中态用浅色底与细短色条标明，不叠加整圈描边。展开时 Logo 与 JunoHub 字标靠侧栏起始边排列，Logo 与导航图标的左缘接近；折叠后 Logo、导航图标与账户头像同轴居中。侧栏标题区与顶栏均为 64px 高，底部分隔线同高；顶栏只显示当前页标题，不重复侧栏字标。顶栏与正文共用同一个 1440px 容器和水平内边距，折叠时内容随侧栏宽度平移，不留下悬浮空隙。小屏使用可关闭的导航抽屉，抽屉与桌面侧栏使用同一套导航样式。
4. 每页只有一个 h1。标题、描述与操作采用 `PageHead` / `PageHeader`；各控制台页面统一 24px 标题、14px 说明文字，标题行高 1.3、说明行高 1.6，两者相隔 8px，网关总览不另设字号。保留现有字体。操作在窄屏进入正常流，不挤压标题。
5. 总览顶部保留供应商、模型路由、访问密钥、今日请求四张指标卡；指标卡直接进入对应详情，注释准确描述资源数量，不把已创建配置写成可调用或有效。总览数字和卡片使用较紧凑的字号与内边距，保留清晰的组间留白，不改变全站字体。下方保留宽度均衡的请求地址与配置进度双栏，请求地址在卡片底部以独立次级表面按身份验证和模型名称分组说明；配置步骤明确显示已配置、下一步和待配置。Token 用量另设宽卡展示，不挤压顶部四卡。
6. 数据必须来自接口，显示千位分隔符；对齐比较使用 `tabular-nums`。时间范围在指标旁说明。Mono 用于地址、凭证和技术标识。
7. 接口成功、配置存在都不能推导“服务可用”。配置状态仅表示资源存在，实际可用性须经过请求验证。缺失数据和错误不能伪装为零。
8. 组件内间距以 8/12/16px 为主；组间 24/32px。描述紧跟所属标题，表格与数据区域不受 prose 最大行宽限制。
9. 用链接导航、按钮执行动作。配置清单必须可进入对应页面；复制有成功反馈与失败恢复文案。
10. 页面在 320px 下不横向溢出。密集表格可在带可访问名称、可键盘聚焦的区域内横向滚动。长地址换行；不要缩小单个数值来掩盖布局问题。
11. 交互必须有可见焦点；图标按钮有名称；状态不能仅靠颜色。保留 Base UI 的弹窗焦点管理及 Escape 行为。
12. 资源卡片按“名称与状态、连接信息、底部操作”排序，删除操作不占据卡片顶部。长技术标识允许换行。供应商、模型路由和密钥页的搜索与添加入口直接使用隔离在 `components/coss-ui/` 的 coss ui `InputGroup` 与 `Button`，模型路由页内的编辑和表单按钮也使用该 `Button`。展示结果数和无匹配时的清除入口；搜索不扫描完整密钥。
13. 表格数字列通过 `Column.align` 统一对齐表头和数据；分页归入表格底部，小屏保留横向滚动提示。
14. 请求入口采用专属深色代码表面 `.endpoint-code`，文字、边框、复制按钮必须在此表面上验证对比度。接入进度使用 shadcn/ui 的 `Progress`，值来自三项真实资源存在状态，首个缺失步骤突出显示；不能推导上游健康。
15. 侧栏区分日常网关操作和管理员功能；账户显示真实角色。登录页保留原有 1024px 双栏卡片、宽松内边距与品牌区和表单区的位置。
16. Token 组成条仅表达输入与输出的实际比例，零值不伪造长度；旁边保留精确数值和直接标签，不代表时间趋势。
17. 表单输入、下拉和日期筛选默认使用 44px 高度。所有搜索使用供应商页的 coss ui `InputGroup`、`InputGroupInput`、`InputGroupAddon` 与 `SearchIcon`，沿用组件默认高度（桌面 32px、小屏 36px）、圆角、内边距、表面和焦点样式；不单独加高度、背景或绝对定位图标，不在部分页面追加清除图标。清空可编辑文本或使用页面已有的重置／无结果清除入口。搜索框旁的身份筛选跟随搜索框高度。输入组合只在外层绘制一次边框。表单下拉统一使用 `SelectField`（shadcn/ui 的 Base UI Select），可搜索选择字段也用同一 InputGroup 外层，Base UI Combobox.Input 通过 render 复用 InputGroupInput，保留选项、键盘与弹窗定位行为。
18. 状态过渡使用明确属性，通常不超过 150ms。不新增装饰性入场动画。尊重减少动态效果，主题切换禁用过渡。
19. 主内容卡片、资源卡片和独立数据表统一使用 16px 外圆角；工具栏、输入和卡片内控件使用更小的圆角。登录与侧栏使用衬线、加粗、斜体的 JunoHub 字标，与 Juno Admin 的字标样式一致；正文继续使用 Geist 与原有中文回退字体，代码和数据使用 Geist Mono。组件保持原有页面的宽松间距，不为了使用组件而压缩布局。资源状态使用带文字的小标签，辅助操作区用低对比度表面分层。

## 共享实现

| 用途 | 实现位置 / API |
| --- | --- |
| 色彩与主题 | `app/globals.css` 中 `--semantic-*`；Tailwind `bg-bg-surface`、`text-muted-foreground`、`border-border-default` 等 |
| 实色面板 | `.surface-card`；现有 `--glass-*` 是兼容别名，指向实色语义 token，导航使用 `bg-bg-chrome` 单独分层 |
| 轻量阴影 | `--shadow-surface`；弹出层单独表达层级 |
| 页面标题 | `PageHead` / `PageHeader`、`.page-heading`、`.page-lead` |
| 总览指标与资源入口 | `MetricCard`、`Card`、`Progress`、`.setup-link`、`.token-track` |
| 配置步骤 | `.setup-link`，真实链接、明确完成状态 |
| 操作 | `Button` / `buttonVariants`，导航使用 `Link` + `buttonVariants` |
| 资源与表单 | `ResourceGrid`、`ResourceCard`、`FormDialog`、`Field`、`FormError` |
| 数据表格 | `DataTable`：完整宽度、表头语义、局部滚动、分页 |
| 基础组件 | `components/ui/` 下的 shadcn/ui Base UI `Sidebar`、`Table`、`Select`、`Combobox`、`Tabs`、`Progress`、`Switch`、`Badge`、`Empty`、`Field`、`Tooltip` 等；项目专属组合写在业务组件中 |

shadcn/ui 采用 Base UI 版本，复用现有 Next.js、Tailwind、Base UI、Lucide 与主题实现。官方 Nova 样式在 `app/shadcn-nova.css` 中限定作用域，再映射到 JunoHub 语义色，保持各页面一致。

## 验证与维护

修改前保存固定数据与视口的截图，再对比修改后同一场景。测试数据只在浏览器测试中拦截，不能写进生产页面。

- 正常、零数据、接口错误、长标识和大数值场景。
- 1440px 桌面、768px 中间宽度、390px 手机与 320px 窄屏；浅色与深色。
- 检查页级溢出、表格滚动、标题数量、主要操作可见性；用量不能被裁切。
- 键盘 Tab、导航抽屉、弹窗关闭与焦点返回、复制成功/失败、主题切换。
- 执行 `npx tsc --noEmit`、`npm run lint`、`npm run build`。
- 人工看首屏层级与实际截图。自动化通过不等于视觉质量已证明，未测试的后端行为和屏幕阅读器需明确记录。

## 应用内控件

用户管理沿用统一页面标题与说明字号，概览使用三张轻量指标卡，数值 24px、辅助文字 12px；加载和错误状态不伪装成零。搜索直接使用供应商页同一套 coss ui `InputGroup`、`InputGroupInput`、`InputGroupAddon` 与 `SearchIcon`，不额外覆盖高度；用户身份下拉复用 `SelectField`，提供全部身份、管理员、普通用户，与搜索组合筛选。两项控件等高，窄屏换行；工具栏移除刷新按钮。用户表格直接使用 coss ui `Table` 与 `Badge`，按用户身份、角色、状态、注册时间、操作分列对齐，长姓名和邮箱可换行，窄屏在表格区域内滚动。详情是独立入口；身份和账户启停集中在编辑用户表单，共用保存。总数置于表格底部，接口分页可继续加载；正常账户和管理员统计来自已显示用户，未全部加载时明确说明范围，搜索和身份筛选也说明当前范围。

所有可见控件使用应用主题绘制，不使用原生 select、title 提示或浏览器校验气泡。AppTooltip 负责悬浮与键盘提示；AppForm 使用 noValidate 并呈现可聚焦关联的错误信息。头像区域提供可点击、可键盘操作的选图入口，同时支持拖放和粘贴；选择图片使用浏览器文件选择器，处理后在表单中预览。保留语义 HTML、浏览器安全边界和现有 Base UI 的键盘及焦点机制。

Tooltip 使用 Base UI 的 `data-anchor-hidden` 状态：触发按钮滚出表格可视区域时隐藏定位层，避免离屏提示通过 Portal 撑开整页。

## 供应商工作区

- Messages 测试和模型路由高级设置共用「1M 上下文兼容标记」开关，默认关闭，仅用于供应商明确要求的兼容请求。测试设置只影响本次诊断；实际转发从已保存路由读取开关。切换到其他上游格式时清除标记，不根据模型名称推断支持。转发合并客户端已有的 anthropic-beta，保留其他标记并去重。
- 修改 JunoHub 预设接口时，保留已兼容的上游格式及适配组合；当前上游格式不兼容时同步请求格式，自定义路径保留，媒体接口进入自定义连接且不猜填供应商路径。请求路径输入支持粘贴同一供应商 origin 的完整 URL，自动提取原始合法路径；不同域名、鉴权信息、查询参数和路径跳转不自动转换。服务器继续只接受合法路径。
- 测试错误保留 HTTP 状态和脱敏后的上游原话；不能仅凭 429 推断余额不足或凭证无效。已发出但收到 429/5xx 的请求显示「未通过」，不显示「待验证」；上游明确返回 Service Unavailable 时说明其报告服务不可用，不能推断更具体原因。

- 供应商是模型路由的上游入口；授权账户是其中独立的调用凭证。平台首次接入创建供应商，已有平台进入现有工作区添加账户，不能把再次授权伪装成新增供应商。
- 供应商卡片与模型路由卡片使用同一头像来源。内置平台显示对应平台图标；自定义供应商可在供应商资料中拖放或粘贴头像，裁剪压缩后保存。移除头像恢复默认图标，模型路由随供应商头像变化。
- 供应商管理使用固定详情工作区，显示供应商名称、账户数和已保存策略；账户编辑使用独立任务弹窗。返回列表入口保持明确。
- 授权账户、分组与容量、调用策略分区呈现。账户资料编辑只更新名称和连接地址；重新授权、更换密钥是独立操作，明确目标账户名称，不混在资料保存中。
- 请求分配统一保存方式、账户顺序和份额；容量独立保存，切换分区保留草稿。显示未保存标记、撤销修改和明确的保存范围；返回列表时确认放弃草稿。修改账户集合前处理尚未保存的分组配置。顶部当前策略只显示后端已保存值。
- 加载失败不能用默认策略覆盖。保存期间锁定对应编辑与离开操作；删除失败保留确认框并支持重试。删除单个账户保留供应商和路由，删除供应商则说明整个资源的影响。
- 多账户允许同优先级，数字越小越优先。权重展示为组内理论份额，只作用于加权策略；最大并发是硬上限。策略编辑保存算法、响应期限、故障冷却和会话保持。
- 健康状态区分可参与调度、限流、冷却、过期和停用，倒计时结束后等待刷新，不直接宣称恢复。列表图标不使用序号暗示调用顺序。
- 验证需覆盖：平台首次接入与已有平台入口、编辑资料不触发授权、凭证更新仅针对选中账户、切换保留草稿、撤销数值输入、放弃确认、请求失败重试，以及深浅色 320/390/768/1440px。

## 客户端集成

- 客户端配置的客户端选择直接使用 coss ui 的 `segmentedControlRootClassName`、`segmentedControlItemVariants` 与 Base UI `RadioGroupPrimitive`、`RadioPrimitive.Root`。各选项显示 16px 平台图标和名称，使用受控选中值；窄屏仅选择栏内部横向滚动，保留方向键切换与可见焦点。
- 安装检测并行查询各工具的安装位置与在线最新版本，本机版本命令最多等待 5 秒并在超时后终止，在线查询最多等待 4 秒。某个工具无法运行或在线查询失败不影响其他工具的检测结果；在线版本未知时不得显示“已是最新”。检测按钮在处理中禁用，整体失败就地显示可重试的错误并保留已有结果。

- 集成拆分为“供应商管理”和“客户端管理”两个页面。供应商管理按 Claude Code、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi 切换独立列表；客户端管理只承担检测、安装和升级。
- 供应商列表支持搜索、拖动排序、复制、编辑、删除、只读连通性检查、当前状态和用量摘要。切换供应商只改目标客户端，不能覆盖其他客户端配置。
- “导入当前配置”保留完整原生配置，包括多模型、能力、费用、请求头和环境变量引用；不要求静态密钥或默认模型。Codex 不导入官方 OAuth token。相同客户端与供应商标识重复导入更新原记录。
- 添加默认进入当前客户端的原生预设，通用供应商另设入口。弹窗表单支持原生字段和完整 JSON 编辑，原生配置加密保存，编辑时经归属校验按需读取。列表不返回密钥。
- 当前使用的配置编辑后同步，其他配置只保存。OpenCode、OpenClaw、Hermes、Pi 添加和移除条目不改变默认模型；已有供应商标识不可修改，复制创建新标识。
- 本机 Rust 组件读写客户端原生配置文件，写入前创建备份并使用原子替换，解析失败时不得覆盖原文件。Claude、Codex 和 Gemini 使用替换式当前供应商；OpenCode、OpenClaw、Hermes、Pi 使用各自的多供应商结构。
- 检测通过本机回环接口就地完成，不打开外部应用。安装、升级和应用供应商配置可以调用本机组件，并在操作完成后把结果返回当前页面。

### 请求限制与普通供应商

普通 OpenAI 兼容供应商和平台授权池使用同一个管理工作区，普通 Key 不伪装为 OAuth。供应商请求限制放在编辑供应商表单，不设独立分区。供应商限制所有模型入口的合计并发/RPM，模型路由的限制放在编辑表单；账户 RPM 在“分组与容量”设置，明确 0 表示不限。模型不能放宽父层限制，入口 RPM 与失败切换实际尝试 RPM 分别说明；并发覆盖整个流式响应。

### 面向使用者的配置呈现

日常界面不展示数据库主键、账户内部编号或用户 ID，以名称和必要的连接信息识别资源。保留模型标识和 OAuth Client ID 等完成配置所必需的字段。配置入口采用“连接密钥／授权账户、请求分配、账户容量”，各自配一句用途说明；选中状态使用描边、底色和勾选共同表达。总量限制在编辑表单中填写，0 的含义在字段旁说明。账户的模型范围默认折叠，列表使用留白和分隔线，减少嵌套面板。

### 连接测试

OAuth 默认通过手动粘贴完整回调地址或授权码完成，不承诺自动返回；localhost 回调页面无法连接时仍可复制地址。区分“打开本次授权页”与“重新生成并打开授权页”，后者会切换会话。不得长期占用官方客户端的回调端口。回调页保留复制入口，不在未确认接收时自动关闭。

OAuth 回调收到授权码仅表示可以提交，不表示账户已验证或保存。完整回调地址必须校验 state，旧回调不能套用新会话。生成新链接时清空旧会话；提交期间禁止重复提交。Token 已兑换但初始化失败时保留分阶段错误，允许在暂存有效期内继续，不能用“会话不存在”覆盖第一次失败原因。

已保存供应商展开实际模型验证时自动获取上游模型列表，支持搜索、选择与刷新；获取失败时可重试或手动填写模型 ID。手动填写后返回列表保留当前值。获取列表不触发生成请求，实际调用仍由验证按钮单独触发。

添加供应商或 API Key 时可使用当前草稿测试连接，不触发保存。修改地址、凭证、平台或测试模型后，旧结果不再显示。模型列表可访问与模型调用成功分别说明；空列表不判为断连，不支持列表接口提示进一步验证，不以 HTTP 200 单独判断成功。实际模型调用由用户明确触发并说明少量用量。已保存供应商按 Key 名称展示结果，测试不修改冷却和调度状态；错误不回显凭证或上游原始错误正文。


### 分组编辑工作区

保留以分组为中心的配置。左侧按调用顺序列出分组，右侧只显示当前组的成员、可加入账户和顺序操作；窄屏上下排列。加入与移出直接更新同一份草稿，不使用主用／备用账户角色表替代分组，不再使用混合勾选或多层弹窗。新建组可为空；移出最后一个成员后组仍保留，用户明确加入账户或移除空组。存在空组时禁止保存并说明原因。

分组、份额和策略统一保存，切页保留草稿，撤销恢复已保存值。编辑份额不重排优先级或重挂载输入框。选择组、加入、移出、顺序调整、新建、空组处理、保存和撤销都需验证；适配深浅色与 320/390/768/1440px。

连接验证区使用独立的灰蓝／炭灰面板，紧凑的“连接检查／模型调用”模式切换，测试操作全宽呈现；等待上游时显示文字状态。测试结果复用 ConnectionTestResultView：小面积状态图标、结果标题、说明、HTTP 与耗时依次呈现，不用整块红绿背景承载正文。多个 Key 用分隔行展示，建议地址与应用地址操作分开，长地址允许换行。已保存供应商点击测试立即打开状态面板；模型调用配置按需展开，结果页可直接重新检查，接口错误就地显示并允许重试。

组内只提供“移除”解除分配，不要求选择其他组。账户进入未分组状态，保留凭证，保存后不参与调度；“加入账户”展开未分组账户列表，加入当前组。普通 Key 与授权账户均持久化该状态，容量编辑不得把未分组账户重新分配。同一供应商内账户名称忽略首尾空格和大小写后不可重复，新增、重命名和重新授权都由后端校验，前端提供就地提示。

分组优先级与组内顺序独立保存。组标题的提前／延后调整整组优先级；账户箭头只调整本组 member_order，移入时追加到组尾。按组内顺序和轮流模式显示账户箭头；比例和空闲优先隐藏箭头并解释列表顺序不决定选择。固定顺序不被普通会话保持覆盖，续接已有响应绑定原账户的例外需说明。最多尝试次数是全请求上限，耗尽后不会继续进入备用组。容量保存及重新授权保留组内顺序。

自定义供应商的所有 Key 共用供应商 Base URL。新增账户和编辑资料仅展示只读地址，测试建议不得覆盖账户地址；后端拒绝账户级地址覆盖，调用与连接测试统一读取供应商地址，包括历史账户。

连接测试只有一个 Key 时仅显示该账户结果，避免摘要与明细重复。建议地址操作进入供应商统一地址编辑草稿，用户保存后才生效；供应商连接密钥页保留统一地址编辑入口，账户地址仍只读。

供应商资料与账户资料是两个独立编辑任务：供应商编辑包含供应商名称与共用 Base URL，账户编辑仅包含账户资料，凭证更新保留独立入口。测试修正地址进入供应商编辑，不进入账户编辑。

模型路由展示实际供应商名称，不以内部 provider_type 回退；新增和编辑均支持美元／百万 Token 的输入、输出价格，未配置与免费明确区分。价格配置持久化，未接入费用统计前不得显示推算账单。

上游模型选择使用 Base UI Combobox，将搜索输入与候选列表合并。输入即展开匹配项，支持忽略大小写、分隔符和多个关键词；不得把不匹配的当前选项强行插入搜索结果。切换供应商或刷新时不显示旧列表与旧错误。保留手动填写和当前选择，使用库的键盘导航、选择和 Escape 行为。

模型路由卡片中，供应商与上游模型使用独立的标签和值行；价格独立分区，输入和输出并列，单位统一说明。仅模型标识使用等宽字，未配置价格使用次级文字。编辑操作靠右，窄屏允许操作组换行。

模型路由使用紧凑卡片：32px 图标、16px 主体内边距、8px 底部纵向内边距；价格压为可换行的摘要行。保持供应商与上游模型分行。此密度仅应用于模型路由，不改变供应商卡片。

模型路由显示上游请求路径并允许普通供应商配置；留空继续按客户端接口自动路由。自定义路径以 / 开头，替换供应商 URL 的路径部分并保留域名，表单显示最终上游地址，不重复拼接 /v1；路径不会转换请求协议。平台授权池使用账户引擎自动路径。客户端仍调用 JunoHub 的标准接口，并把 model 填为对外别名；“查看接入指引”作为标题区右上角的次级链接按钮，不单独显示接入提示横条。

管理区新增“接入指引”，文档使用 Markdown，管理员可编辑、实时预览、保存和下载 .md；登录用户可阅读。内容持久保存在服务端，按版本校验防止并发覆盖，保存错误保留草稿。浏览器标签页保留未保存草稿。预览使用 react-markdown 与 remark-gfm，不执行原始 HTML；页面只有一个 h1，代码块和表格只在内部横向滚动，沿用现有字体、页面字号及深浅主题。

访问密钥支持创建后再次查看、复制，完整值按需获取，列表只展示掩码。旧哈希密钥说明首次成功鉴权后可补存，不伪造恢复值。卡片使用紧凑布局，分别展示请求数、输入/输出 Token 与美元估算消耗；未计价请求单列，不把缺价格或缺用量算作免费。金额按请求完成时配置累计，历史金额不随之后改价变动。

“我的密钥”独立入口始终由服务端只返回当前账户的密钥，管理员也不在此页看到他人的密钥；网关总览中的本人密钥数量和客户端配置入口指向此页。管理区的“访问密钥”保留管理员查看所有用户密钥和归属信息。两页共用紧凑表格与创建、查看、复制、编辑、删除操作；普通用户的旧访问密钥地址继续仅显示本人数据。搜索覆盖密钥名称和归属用户，窄屏表格可横向滚动；删除确认包含归属信息。

两个密钥页面的搜索框直接使用 coss ui `InputGroup`、`InputGroupInput`、`InputGroupAddon` 和 `SearchIcon`，与蓝色默认 `Button` 创建入口放在同一工具栏，结果数位于起始侧，窄屏换行。空状态创建入口也使用同一 `Button`。创建和编辑弹窗的名称输入使用 coss ui `Input`，取消与提交使用 coss ui `Button` 并在末尾对齐，提交使用组件的加载状态。

密钥表格使用紧凑行距，输入和输出 Token 分列右对齐，单页隐藏分页底栏；用户与密钥列保留最小宽度，避免窄屏逐字断行。滚动区域的键盘焦点框向内绘制，避免被外层裁剪成单条蓝线。

密钥查看弹窗使用只读单行输入框，获得焦点时全选，复制/关闭放在独立右对齐操作栏，避免按钮挤占密钥宽度导致末尾单字换行。密钥列表使用统一尺寸的查看、编辑图标按钮，保留悬停提示和可访问名称；更多菜单容纳复制与删除；操作表头和按钮组统一起始对齐。编辑允许修改名称和状态，保留归属、密钥值、模型权限、有效期和消耗记录；失败保留草稿。

密钥表格按用户要求统一左对齐，包括请求数、Token、金额和操作；数值保留等宽数字。表头与单元格采用相同内边距，操作图标抵消按钮内部留白，使图标与列标题起点一致。

密钥表格使用固定列布局：身份列承担剩余信息密度，状态、用量和操作列保持稳定宽度。操作统一使用 36px 图标按钮，状态以圆点和文字共同表达；桌面不因单条短数据拉散列间距，窄屏在表格区域内滚动。

请求日志筛选必须由服务端执行并作用于完整结果集，不能只过滤当前分页。管理员可筛选并查看所有用户；普通用户只能查看本人。筛选包含用户、模型、实际供应商名称、开始/结束日期和响应状态，分页与刷新保留当前条件，清除操作一次恢复全部日志。

请求日志筛选控件直接排列在页面上，整组不使用外层卡片、背景、边框或内边距。用户、请求模型和供应商分别直接使用 coss ui `InputGroup` 与 `SearchIcon`，按内容定宽并在窄屏换行；状态直接使用 coss ui `Combobox` 的默认输入与弹层，不额外添加状态图标，日期范围使用 coss ui `Popover`、`Calendar` 与 `Button`。重置操作置于筛选控件下方；结果数置于日志表格最下方，和分页操作并列，窄屏无需横向滚动也能看到。筛选区与日志数据表保持清晰留白，单页隐藏分页按钮。

日期范围使用单一触发按钮与紧凑范围月历。弹层提供今天、近 7 天、近 30 天和本月预设；完整区间后的下一次点击重新设置开始日期，第二次点击设置结束日期，只有区间完整后才能应用。

请求日志的用户、模型和供应商搜索由服务端分别执行不区分大小写的部分匹配，输入内容作为各自独立条件，允许逐项清除。服务端将输入中的 `%`、`_` 和反斜杠作为普通字符。界面统一使用“搜索、找到、重置搜索”，状态保持枚举选择，日期保持范围日历。

请求日志主表直接使用 coss ui 的 `Table`、`TableHeader`、`TableBody`、`TableRow`、`TableHead`、`TableCell` 与 `TableCaption`，普通用户与管理端共用同一个日志表格实现，表头使用 `bg-bg-sunken/60`、单元格使用 `px-4 py-3.5`，与管理端表格一致；状态使用 coss ui `Badge variant="outline"` 和统一的 `gap-1.5 px-2`，同时显示色点、状态码和文字。总数及分页置于表格滚动区域外的底栏。固定展示时间、用户、Key 名、请求模型、供应商、状态、耗时、Token 和详情。Key 名与供应商名按请求发生时保存快照，避免资源改名或删除后丢失归属；上游模型、输入/输出 Token 和错误信息收进详情弹窗。

- 集成中的添加和编辑使用网页弹窗：桌面最大宽度 52rem，四周保留页面背景，标题与操作栏固定、表单内部滚动。关闭使用右上角图标；预设列表限高滚动，避免大量预设挤走配置字段。窄屏仍保留外边距，不展开为整页。

- 原生供应商表单的常用字段必须有专用控件，不能以 JSON 编辑器代替：Claude 支持认证字段、分层模型映射和子代理模型；Codex 支持推理强度；多模型客户端支持协议选择、请求头、模型上下文/输出上限、输入类型、推理能力和价格。JSON 用于完整查看及扩展参数。
- “获取上游模型”通过 Rust 本地组件执行只读请求，沿用 CC Switch 的版本路径与兼容子路径尝试规则；模型搜索支持包含匹配，多模型客户端可批量加入，已有配置不被覆盖。

- 供应商列表中的客户端接管与自动故障转移是独立开关；未接管时禁用故障转移。代理设置与故障转移队列使用独立弹窗，队列以 P1、P2 标注优先级，不再组合成“本地路由”表单。编辑队列不得隐式切换当前供应商或改写客户端配置。

- 集成供应商预设仅使用 CC Switch 原始目录（包括其通用供应商目录），JunoHub 是唯一额外预设。不得自行增加其他品牌、网关模板或默认推荐项；用户自行创建的供应商不受预设目录限制。

- 供应商列表直接使用 coss ui 官方源码的 `InputGroup`、`InputGroupInput`、`InputGroupAddon` 和 Lucide `SearchIcon` 组成搜索框，使用 coss ui 默认蓝色 `Button` 作为“添加供应商”入口；仅调整外层布局，不改组件内部样式。结果数在左，搜索和按钮在右，窄屏按可用宽度换行。空状态仅提供添加供应商；不拦截浏览器查找快捷键。添加弹窗内的上游预设搜索保持不变。不提供“导入当前配置”按钮。

- 用户明确排除 NewAPI：不在添加预设、通用供应商快捷入口或类型选择中展示 NewAPI。移除客户端预设区的“NewAPI／自定义网关／管理”额外快捷按钮行，保留 JunoHub 直接入口。历史供应商配置不随入口移除而删除或改名。

- JunoHub 是客户端预设列表中的唯一额外特殊预设。选择后在当前客户端范围内配置名称、访问密钥和模型，不跳转通用供应商，不展示多应用开关；保存为当前客户端的供应商。既有通用配置不自动迁移。

- 移除通用供应商产品概念：添加、编辑均绑定当前客户端，无通用页签、跨客户端共享创建流程或多应用开关。JunoHub 仅保留当前客户端的特殊预设。
- 公共配置功能已删除：不提供页面入口、编辑弹窗、启用勾选或保存接口，不再读取旧文件合并到新配置。旧标记仅用于切换时清理及备份恢复，不重新应用旧片段。

模型路由表单和卡片分为“调用上游平台”与“通过 JunoHub 调用”两部分。上游请求格式使用一个 SelectField，提供常见对话格式预设及带实际格式名称的“自定义路径”；仅自定义时展示必填请求路径，完整上游地址始终直接展示，不放进高级设置。JunoHub 侧包含对外别名、预设接口和完整客户端调用地址，不展示密钥用途、协议转换和路径规则等说明段落。对外路径由预设固定，上游路径独立配置。协议组合只允许同协议直通及已实现的 Messages → Chat Completions 适配，未实现组合禁止保存。新建路由分别持久化两侧协议和上游连接模式；上游路径、鉴权和价格独立配置；修改 JunoHub 预设接口时，已兼容的上游协议保留，不兼容时同步为可接收该接口的格式。切回对话格式时清除无效的任务返回设置。切换预设与自定义保留当前弹窗中的自定义路径草稿。已有自定义路径和转换配置不因打开编辑而改变。复用 Input、SelectField、Field，保持字体与 24px／14px 页面字号，不添加供应商专属路径预设。

模型路由弹窗在 800px 以上使用并列的两侧配置，小屏按上游、JunoHub 的顺序排列。供应商、模型、请求格式和完整地址直接可见；自定义路径按选择显示。鉴权和返回方式复用 Base UI Collapsible 收入“高级设置”，已有非默认设置编辑时自动展开。任务查询路径在任务模式下直接显示。价格为可选折叠区，已有价格或校验失败时展开，折叠不丢失草稿。取消和保存位于独立固定底栏，表单内容内部滚动；提交错误显示在操作旁。

上游预设保留 Chat Completions、Responses 和 Anthropic Messages 三种常用格式。JunoHub 提供全部 12 个固定接口：三种对话、图片生成、图片编辑、视频生成、音频生成、语音合成、语音识别、向量化、搜索和文本重排；自动模式仅用于已有路由及授权池。选择扩展接口时，上游使用自定义路径，不套用 JunoHub 的扩展路径作为供应商预设。切换自定义保留当前请求格式；选择 JunoHub 接口时，兼容的上游格式保持不变，否则同步为同一格式，路径仍由用户填写；历史转换配置打开及原样保存时保持不变。

切换上游预设时，兼容的 JunoHub 格式保持不变；不兼容时调整为同格式入口，清空自定义路径。自定义模式切换 JunoHub 接口保留路径草稿，同时同步请求格式，防止向量化与语音等不相关能力组合。对话格式不使用任务查询模式，切换到对话时改为同步／流式。默认路径仅用于明确选择的三种上游预设，自定义路径为空时不显示虚构的完整地址，禁止保存及测试。

模型路由提供“测试上游”，使用未保存草稿中的上游模型、格式、鉴权与自定义路径，凭证从归属供应商服务端读取；发送一次短请求并提示可能产生用量。普通供应商仅测试参与调度、不在冷却且允许该上游模型的账户，保留 * 通配规则，显示其名称，不改变调度与冷却状态；授权池使用账户引擎发送所选模型请求。HTTP 2xx 还须通过响应格式验证才能显示通过，提供状态码与耗时；改动配置后旧结果失效，测试不保存路由。JunoHub 接口统一使用预设路径，不增加自由路径字段。


### 文件中转与模型发现

图片编辑和语音转写的 API Key 路由接收有界文件表单，模型目录以服务端 request_formats 展示网关支持的请求类型。模型详情与接入指引复用 SelectField 切换 JSON/文件示例；curl、Python requests 与 Node.js 原生 FormData 三种语言沿用同一代码区域。保留供应商要求的文件字段名与额外参数，说明 32MiB 总量限制，不声称所有供应商支持这些字段。示例不手动设置 multipart Content-Type 或 boundary。管理员目录与普通用户目录保持同一呈现，账户引擎不提供文件选项。

标准 /v1/models 的 id 保留别名；安全的 junohub 扩展提供客户端接口、返回方式、接收格式和价格，受同一密钥授权与路由启用规则约束，不公开上游模型、路径、凭证或计费用量指针。接入文档的新模板保留已保存自定义文档。

### 运行监控与调用治理

管理员导航增加「运行监控」，普通用户导航及 API 权限均不开放。概况使用现有 Card、coss Button/Badge/Table、SelectField 与 Tabs，包含调用表现、请求趋势、依赖和后台工作、上游候选状态、任务与用量。数据缺少样本显示「—」，旧运行快照明确过期；请求趋势提供可展开的数据表与不依赖颜色的失败虚线。明暗主题复用语义颜色，不改字体。

告警、任务和操作审计提供同样的可滚动表格、空态、加载失败状态与底部分页；配置版本冲突不能静默覆盖。任务重查不再次发起生成。个人请求日志与管理端仍共用页面，增加请求 ID 搜索和详情字段，保持用户数据隔离。

模型、供应商、密钥与用户的请求限制直接放入对应编辑表单，复用 RequestLimitsFields：最大并发与每分钟请求数两个数字输入，0 表示不额外限制。移除独立限制按钮、弹窗及供应商的总量限制 Tab；限制与基本配置共用保存/取消，在同一个数据库事务保存。编辑加载失败不得以 0 覆盖已有配置。用户身份、状态与跨全部密钥的共享限制集中在编辑用户弹窗，用户详情保持只读。模型的限制位于右侧客户端配置中，价格之前。保存通知移至右下角，避免遮挡弹窗右上角关闭按钮。

模型路由的完整上游地址通过管理员专属 model/preview 接口解析，复用实际转发的路径算法；预览无上游网络请求，不消耗模型额度。切换格式后不展示上次解析结果；解析失败不能假装有正确地址。自定义路径只指定目的地，不声明能转换任意供应商请求体。账户引擎对外可固定为 Chat Completions 或 Responses，已有自动入口保留兼容且展示两个地址；不能选择引擎不支持的媒体入口。编辑同一模型类型保留原有多模态能力；切换普通供应商保留路由协议、路径和价格，只有切换账户引擎连接类型时重建上游配置。保存按钮仅在提交期间禁用，错误关联具体字段并聚焦，任务格式与查询路径也须校验。

SelectField 是不带清空操作的受控选择器；动态选项注册发出的 null 不视为用户选择，不得清空已选值。上游格式选择只接受已知协议值，避免空值回调把自定义模式误存成预设。Messages 入口配置自定义 Chat Completions 路径时，单个请求格式下拉直接提供对应格式，不新增第二个格式字段。

账户安全：密码修改成功后清除本机登录态并返回登录页；旧会话在服务端失效，身份变化和停用/重新启用也撤销旧会话。保留既有设置弹窗组件、字体和布局。

新增自定义供应商通过平台接入弹窗进入表单时，限制立即初始化为 0；尚未创建的资源不读取后端限制。编辑已有供应商才加载已保存值。连接检查返回模型后显示同一套搜索选择组件，选择模型进入调用验证；切换回连接检查保留列表，地址、Key 或平台变化后旧列表立即隐藏。

添加供应商的模型调用区可直接获取／刷新模型：读取当前地址和凭证的模型列表，不发起生成。测试模型字段在搜索选择与手动填写之间切换，不同时显示两个输入。选择模型后再点击验证模型调用；获取失败显示具体错误并保留手动填写。

供应商模型测试必须按所选请求格式发送：复用路由探测器的 Chat Completions、Responses、Messages 请求体、路径和鉴权，新增及已保存供应商共用格式／鉴权选择字段；模型列表获取保持独立。结果展示实际 POST 路径，HTTP 失败保留长度受限且已隐藏密钥的 JSON 错误说明，不能仅凭模型列表推定可调用，也不能把供应商的客户端限制归结成 Key 错误。
